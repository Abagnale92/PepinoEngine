PEPINO LANGUAGE

Facile come un racconto, preciso come il C++

Pepino Language è il linguaggio di Pepino Engine. Si scrive con parole italiane o inglesi, controlla i tuoi errori prima di partire e te li spiega come farebbe un amico. Sotto la superficie gestisce la memoria con le regole del C++ moderno, senza puntatori pericolosi. Serve per scrivere blocchi del motore e, con il comando pepino, qualsiasi altro programma.

Le idee

Sei scelte, ognuna pensata per chi impara e per chi deve fare sul serio.

bilingue

La tua lingua

Le stesse parole in italiano e in inglese (se/if, ripeti 3 volte/repeat 3 times). Un pulsante riscrive il programma nell'altra lingua, lasciando intatti i tuoi nomi.

memoria

Come il C++, ma sicura

Valori veri: b = a fa una copia. sposta passa senza copiare. I parametri sono prestiti. Quando un valore finisce, si distrugge subito. Niente puntatori nulli o «appesi».

tipi

Tipi senza scriverli

Il compilatore deduce i tipi da solo e trova gli errori prima di partire. Una funzione senza tipi diventa un modello, come i template del C++.

unità

Numeri con le unità

4 tile/s, 0.5 s, 90°: i conti si convertono da soli e Pepino ti ferma se sommi un tempo e una distanza.

tempo

Aspettare è facile

aspetta 2 s dentro una funzione, e il gioco continua a girare. Niente callback, niente macchine a stati.

gentile

Errori che spiegano

«Non conosco «punto»: forse volevi dire «punti»?». Liste che partono da 1, = che nei se vuol dire «uguale», prove integrate con prova.

Primo programma

Il rientro (gli spazi a inizio riga) dice cosa sta dentro cosa: dopo i due punti le righe vanno più a destra. # inizia un commento.

Dentro le stringhe, {…} inserisce un valore: "Hai {punti * 2} punti". Per scrivere una graffa si usa {{.

Le variabili nascono la prima volta che dai loro un valore: punti = 0. Da lì in poi hanno quel tipo: punti = "tanti" è un errore. Si può scrivere il tipo: nemici: Lista di Testo = []. Le costanti non cambiano: costante GRAVITÀ = 9.8.

Una variabile creata dentro un blocco (un se, un ciclo) finisce con il blocco. Se la crei in tutti i rami di un se … altrimenti, esiste anche dopo.

se punti = 10:              # «=» nelle condizioni vuol dire «uguale» (va bene anche ==)
    scrivi("bravo")
altrimenti se punti > 5:
    scrivi("quasi")
altrimenti:
    scrivi("riprova")

Funzioni

funzione saluta(nome: Testo, saluto = "Ciao") -> Testo:
    ritorna "{saluto}, {nome}!"

saluta("Anna")                        # "Ciao, Anna!"
saluta(saluto: "Ehi", nome: "Bo")     # argomenti con il nome, in qualsiasi ordine

funzione doppio(x):                # senza tipi: è un modello
    ritorna x + x
doppio(21)   doppio("ab")          # 42 e "abab": due versioni, ognuna controllata

pari = numeri.filtra(n => n % 2 = 0)  # funzione veloce

Il tipo restituito si può omettere: lo deduce Pepino. Una funzione che non restituisce niente non ha bisogno di ritorna. Le funzioni veloci (x => …) si usano dove serve una funzione (per esempio in filtra, trasforma, ordina_per); le variabili locali che usano vengono copiate quando nascono.

Tipi

tipo Punto:
    x: Numero = 0
    y = 0                            # il tipo lo dà il valore
    nome: Testo                      # senza valore: va dato quando lo crei

    funzione lunghezza() -> Numero:
        ritorna radice(x * x + y * y)   # i campi si usano per nome (o con questo.x)

    funzione sposta_di(dx, dy):
        x += dx
        y += dy

    quando crea:
        scrivi("nasce {nome}")
    quando finisce:
        scrivi("addio {nome}")          # parte nel momento esatto in cui il valore sparisce

p = Punto(x: 3, y: 4, nome: "P")
scrivi(p)                          # Punto(x: 3, y: 4, nome: "P")
scrivi(p = Punto(3, 4, "P"))          # vero: si confrontano i valori

Pepino capisce da solo quali funzioni cambiano i campi (come sposta_di): si possono chiamare solo su valori che si possono cambiare.

Memoria come il C++

Ogni valore ha un solo proprietario: una variabile, un campo, un posto di una lista. Da questa regola viene tutto il resto.

a = Zaino("Anna")
b = a                       # COPIA: una fotocopia, cambiare b non cambia a
c = sposta b                 # SPOSTA: c prende il valore senza copiarlo; b non si usa più

funzione conta(z: Zaino):       # PRESTITO: la funzione legge senza copiare e senza cambiare
    ritorna z.oggetti.lunghezza

funzione riempi(cambia z: Zaino):  # CAMBIA: la funzione modifica la variabile di chi chiama
    z.oggetti.aggiungi("acqua")
riempi(cambia a)               # si scrive anche nella chiamata: così si vede

funzione tieni(prendi z: Zaino): …  # PRENDI: la funzione diventa proprietaria (copia, o «sposta» per regalarlo)
In PepinoNel C++Che cosa garantisce
b = acostruttore di copiaNessun valore è condiviso per sbaglio.
b = sposta astd::moveIl compilatore vieta di usare a dopo (anche «forse spostato» nei rami, e dentro i cicli).
parametro normaleconst T&Nessuna copia, nessuna modifica.
cambiaT&Una sola via di modifica per volta: f(cambia x, cambia x) è un errore.
prendiparametro per valoreLa funzione possiede il valore e lo distrugge alla fine.
quando finiscedistruttore (RAII)Parte subito, in ordine inverso, anche con ritorna anticipato ed errori; mai due volte.
T? e niente(puntatore nullo)Non esistono valori nulli nascosti: il tipo lo dice e il compilatore obbliga a controllare.

Non esistono riferimenti da tenere da parte (i prestiti durano quanto la chiamata), quindi non esistono puntatori «appesi» e non servono le annotazioni di durata di Rust. Mentre scorri una lista con per ogni, quella lista non si può cambiare: niente elementi saltati o doppi.

Sincerità: oggi Pepino si traduce in JavaScript, dove la memoria la libera il browser. Le regole però sono rispettate alla lettera (copie vere, distruzione nel momento esatto, niente condivisioni), e sono proprio quelle che servono a un futuro compilatore nativo senza garbage collector.

scrivi(strada / 1 tile)             # 12: quanti tile

Un numero senza unità va d'accordo con tutto: le unità servono a trovare gli errori, non a complicare i conti. Nei blocchi, una proprietà scritta proprietà velocità = 4 tile/s compare nell'Inspector in tile/s e nel codice vale già in pixel al secondo.

Aspettare

quando inizia:
    ripeti 3 volte:
        oggetto.visibile = falso
        aspetta 0.2 s
        oggetto.visibile = vero
        aspetta 0.2 s
    aspetta finché oggetto.x > 100     # aspetta che succeda qualcosa
    aspetta                           # un fotogramma

Una funzione che aspetta (o chiama funzioni che aspettano) continua da dove si era fermata, mentre il resto del gioco va avanti. Non si aspetta dove bisogna rispondere subito: in quando aggiorna, nelle condizioni, nelle funzioni veloci. Nel comando pepino l'attesa è vera: il programma si ferma per quel tempo.

Le parole italiane

Cinque parole che il mondo conosce già: si scrivono uguali in un programma italiano e in uno inglese, e il pulsante che traduce le lascia come sono. Valgono solo dove servono, quindi pizza = 3 resta una variabile qualsiasi. Si possono scrivere anche con l'iniziale maiuscola o tutte maiuscole (MAMMA MIA!).

ParolaChe cosa fa
mamma mia! "…"un errore grave: ferma il programma, nessun tenta lo copre (i quando finisce partono lo stesso)
pizza Tipo:crea un valore un ingrediente per riga: i campi di un tipo, gli elementi di una Lista, le coppie di una Mappa
spaghetti valore:una catena di passi: ogni riga riceve il risultato della riga prima
bravo:dopo tenta … se errore: parte solo se è andato tutto bene
cappuccino 2 s:fa il blocco più tardi (o in parallelo, senza durata) e intanto il codice va avanti

mamma mia! — l'errore grave

funzione pesca(cambia mazzo: Lista di Testo) -> Testo:
    se mazzo.vuota:
        mamma mia! "il mazzo è vuoto: qualcuno ha pescato troppo"
    ritorna mazzo.togli_ultimo()

fallisci è l'errore da cui chi chiama può rimediare con tenta; mamma mia! vuol dire «questo non deve succedere mai». Il programma si ferma con Mamma mia! il mazzo è vuoto… (riga 3); nell'engine si ferma il blocco e la Console dice script e riga. Anche da sola: mamma mia!. Il punto esclamativo serve solo qui: per dire «non» si scrive non.

pizza — creare su più righe

eroe = pizza Personaggio:
    nome = "Lucia"
    vita = 3
    zaino = pizza Lista:          # una pizza dentro l'altra
        "pozione"
        "chiave"

prezzi = pizza Mappa di Testo a Numero:
    "margherita" = 6
    "diavola" = 7.5

È la stessa cosa di Personaggio(nome: …, vita: …), […] e {…}, scritta un ingrediente per riga: comoda per i valori grandi (carte, nemici, tabelle). Il tipo scritto controlla gli ingredienti, e se manca un campo senza valore pronto Pepino lo dice. Siccome continua nelle righe sotto, va da sola alla fine della riga: dopo =, dopo ritorna, come valore di un campo.

spaghetti — una catena di passi

funzione in_euro(n: Numero) -> Testo:
    ritorna "{arrotonda(n, 2)} €"

conto = spaghetti ordini:
    filtra(o => o.pagato)
    trasforma(o => o.prezzo)
    somma()
    in_euro()                          # una funzione tua: riceve il valore come primo argomento

titolo = spaghetti nomi:
    ordina()                           # cambia il valore: si va avanti con quello cambiato
    inverti()
    unisci(", ")

Ogni riga riceve il risultato della riga prima. Se il nome è un metodo del valore (filtra, unisci, un metodo del tuo tipo) si chiama su di lui; altrimenti è una funzione che riceve il valore come primo argomento: sconto(10) diventa sconto(valore, 10). Un passo che non restituisce niente (ordina, scrivi, una funzione con cambia) lascia andare avanti lo stesso valore, magari cambiato. Le proprietà si scrivono senza parentesi (lunghezza), e anche i campi di un tipo.

Gli spaghetti non cambiano mai l'originale: nomi resta com'era. Il valore si copia solo se un passo lo cambia (così non nascono copie inutili, e nessun quando finisce parte per niente); con spaghetti sposta nomi: non si copia nemmeno allora.

bravo — è andato tutto bene

tenta:
    età = numero(chiedi("Quanti anni hai? "))
se errore problema:
    scrivi("Non è un numero: {problema}")
bravo:
    scrivi("Tra dieci anni ne avrai {età + 10}")

bravo parte solo se il tenta è finito senza errori, e vede le variabili create dentro tenta (senza bravo finiscono con il blocco). Un errore dentro bravo non finisce nel se errore: il gestore non nasconde errori che non c'entrano. In inglese: try: … if error problem: … bravo: ….

cappuccino — dopo, o in parallelo

blocco Bomba "Bomba":
    proprietà miccia = 3 s, "Miccia"
    quando tocca altro:
        cappuccino miccia:             # tra 3 secondi…
            oggetto.distruggi()
        suona("tic")                    # …ma questa riga parte subito

    quando inizia:
        cappuccino:                    # in parallelo: lampeggia per sempre
            ripeti:
                oggetto.visibile = falso
                aspetta 0.2 s
                oggetto.visibile = vero
                aspetta 0.2 s

aspetta vuol dire «mi fermo io»; cappuccino vuol dire «lo faccio dopo (o a parte), e intanto vado avanti». La riga dopo il cappuccino parte sempre prima di lui. Dentro si può aspettare, e siccome chi lo ordina non aspetta, si può ordinare anche dove non si può aspettare (quando aggiorna); non nelle condizioni, in quando finisce e nelle funzioni di un tipo.

Le variabili locali usate dentro sono copie prese quando lo ordini: si leggono ma non si cambiano. I campi del blocco, le variabili di tutto il programma e gli oggetti dell'engine sono quelli veri. Nell'engine il cappuccino appartiene all'oggetto: se l'oggetto sparisce prima, non arriva (e le sue copie si distruggono). Nel comando pepino il programma finisce quando sono finiti anche i cappuccini; nelle prove il tempo passa subito.

Un esempio con tutte e cinque: npm run pepino -- esegui samples/pepino/pizzeria.pep.

Nell'engine: i blocchi

Nella scheda Codice il pulsante + Pepino crea uno script. Ogni blocco diventa un blocco dell'Inspector (in «Aggiungi blocco» → Personalizzati), e le sue azioni, condizioni ed eventi si usano nelle Regole.

blocco Passeggia "Passeggia":
    descrizione "Va avanti e indietro."
    richiede Body                            # aggiunge il Corpo e rende «corpo» sempre presente
    proprietà distanza = 3 tile, "Distanza", da 0 a 20
    proprietà suono: Suono = "", "Suono del giro"
    evento giro "Ha finito un giro"

    partenza = 0                              # la memoria del blocco

    quando inizia: …      quando aggiorna: …      quando fisica: …      quando dopo: …
    quando finisce: …     quando tocca altro: …    quando evento colpito: …

    azione salta(forza = 3) "Salta":
        corpo.vy = -forza * 1 tile/s
    condizione lontano "È lontano":
        ritorna assoluto(oggetto.x - partenza) > distanza
    funzione aiuto(): …                      # funzioni interne del blocco

Dentro un blocco emetti giro manda un evento alle Regole. Tipi delle proprietà: Numero, Intero, Testo, TestoLungo, SiNo, una scelta (diventa un menu), Suono, Immagine, Modello, Etichetta, Gruppo, Colore, NomeScena, Variabile, Dialogo, Tasto.

Il comando pepino

Lo stesso linguaggio funziona anche da solo, per programmi da terminale, giochi di testo, piccoli strumenti. Si costruisce con npm run build:pepino (un solo file, dist/pepino/pepino.mjs, che gira con Node) oppure si usa direttamente:

npm run pepino -- esegui samples/pepino/indovina.pep
npm run pepino -- controlla gioco.pep       # solo gli errori
npm run pepino -- prova gioco.pep           # le prove
npm run pepino -- traduci gioco.pep en      # riscrive con le parole inglesi
npm run pepino -- js gioco.pep              # il JavaScript generato
npm run pepino -- nuovo ciao.pep            # un primo programma

I comandi esistono anche in inglese (run, check, test, translate, new). Con npm link il comando pepino diventa disponibile ovunque.

Errori gentili

Pepino trova gli errori prima di partire e li scrive in italiano o in inglese, con la riga e un suggerimento quando può.

Errore alla riga 2 di gioco.pep: 2 | scrivi(punto) | ^^^^^ Non conosco «punto»: forse volevi dire «punti»?
«x» è stato spostato alla riga 3 (con «sposta»): non c'è più. Dagli un nuovo valore prima di usarlo.
«nemico» potrebbe essere niente: controlla prima con «se nemico != niente:».
Non puoi sommare un tempo (s) e una lunghezza (px): sono grandezze diverse.
Non puoi cambiare «nemici» mentre lo stai scorrendo con «per ogni» (riga 9). Usa .togli_se(…) o una nuova lista.
«lista» è solo prestato alla funzione, che può leggerlo ma non cambiarlo. Scrivi «cambia lista» nei parametri, oppure lavora su una copia: copia = lista.
